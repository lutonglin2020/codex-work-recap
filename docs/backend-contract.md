# 后台契约

后台将采集、模型评估和界面展示分开处理。默认由 Python 标准库实现，所有持久化数据属于本项目，不修改原 Codex 会话或工作项目。

## 信息流

```text
本机 Codex 持久化会话
  → app-server 只读采集
  → 时间窗口、活动重心、来源去重
  → codex exec 在线归纳
  → SQLite 保存结果
  → display.json 原子快照
  → Windows 小窗按展示策略读取
```

`service.py` 约每 60 秒调度一次 `Engine.tick()`，同时提供可读快照。采集或模型调用不会阻塞状态读取，同一实例的 tick 不重入。MCP 入口经本地文件 IPC 与后台通信；默认服务不监听 TCP/UDP 端口。

## 采集范围

`adapter.py` 自行启动 stdio `app-server`，通过 `thread/list`、`thread/read` 和实验性的 `thread/turns/list` 读取本机持久化主会话。包含归档会话，排除临时会话、子代理、摘要自身运行和 fork 继承副本。

每个归档状态最多读取 3 页 × 16 个会话，每会话最多 4 页 × 20 轮。超出采集范围时通过统计字段披露；这不是桌面实时事件订阅，也不覆盖其他主机或云端聊天。

只有终止状态和结束时间都明确的轮次才能成为模型证据。未结束轮次只作活动线索；轮次结束本身不证明业务已经完成。材料仅包含用户请求和最终助手答复，排除分析过程及原始工具日志。

来源按稳定 ID 和内容 hash 去重。生成成功时记录实际引用的来源；模型明确判断没有新进展时，将本批材料记为已评估。失败不推进处理记录，处理状态与用户已读状态分别保存。

## 时间和取材

日期按 `Asia/Shanghai` 计算：晨间 06:00～12:00 的每日首次自动评估取昨天自然日；没有昨日素材则静默。其余自动评估和强制 `auto` 取最近 60 分钟。显式 `today`、`yesterday` 请求单独处理。

窗口外材料不补入本轮。取材预算优先分给近期持续推进的工作，其他会话保留有限短候选；正文长度不作为工作量权重，也不平均分配最终摘要篇幅。尚未结束的活动能帮助识别当前重心，但不能支撑“已完成”的结论。

单批模型材料最多 20 条、约 13,000 字符。近期旧摘要只作去重背景：最多 3 条、每条 400 字符，不作为事实来源，不能借此扩大当前窗口。

## 模型调用

通过官方 `codex exec` 子进程调用 `gpt-6.1-sol`，推理等级 `medium`。当前显式指定 ChatGPT 登录、`--ignore-user-config`、`--ephemeral` 和只读沙箱，移除该子进程的 API Key 环境变量，因此不直接支持 API Key 或自定义服务登录。

沿用本机 Codex 登录，不提取或复制认证文件。推理在线完成，并受登录账号的模型权限、额度和网络条件约束。调用在自身临时目录中进行，不恢复或发送消息到原会话。

提示和运行配置禁用工具使用，结果事件若出现工具调用则拒收；这些约束不能代替底层权限隔离。执行限时 180 秒，临时 schema 和结果文件在结束后清理。诊断只保留耗时、用量、退出码、错误类别和验证计数，不保留完整模型正文或认证。

模型结果包含：

- `overview`：展示用短正文；每项进展一句，只保留结果和必要影响或状态。
- `work_items`、`brief_points`、`suggestions`：结构化结果和证据引用，默认小窗不展示详情。
- `should_surface`：是否值得展示；为 `false` 时允许空正文，保持安静。
- `next_review_minutes`：20～60 分钟的建议再评估间隔。
- `display_after_idle_seconds`：15～300 秒的建议展示停顿。
- `timing_reason`：调度判断依据。

来源引用使用当批 `S1`、`S2` 等别名，动态 JSON Schema 限定可选值；通过验证后再精确映射回原来源 ID。未知引用拒收，不猜测修正。

## 调度和状态

没有新增材料不调用模型；有材料时先做本地防抖，再让模型判断是否有实质成果。单次明确成果也可触发评估，不设置必须积累多轮的门槛。显著新增或来源临近窗口边界时可提前评估，失败使用有界退避。

“再次评估”和“展开小窗”是两个决定。界面还会检查空闲、全屏和展示冷却；悬停仅读缓存。`should_surface=false` 不属于错误，不能把占位文字当作工作回顾。旧摘要只在自身有效展示期内保留，不冒充当前窗口的新成果。

引擎状态包括 `idle`、`collecting`、`summarizing`、`ready`、`paused`、`error`。暂停不启动新任务；已经开始的模型调用可能继续结束，但若返回时仍处于暂停状态，则不保存该次摘要。`snapshot()` 返回摘要、来源和统计，`mark_seen()` 只更改本项目的已读记录。

## 本地存储与边界

默认目录为用户主目录下 `.codex/work-recap-data`，`WORK_RECAP_DATA` 可覆盖。SQLite 来源缓存保留最近 14 天、最多 600 条裁剪记录，另保留最多 48 份摘要和 128 个事件，日志有界保留。运行 token、锁、IPC 消息和历史工作内容均是本机数据，不应随源码发布。

Windows 后台通过桌面 Explorer 独立启动，使用单实例锁；登录自启由 `scripts/startup.ps1` 添加。可选 hooks 只提供活动提示，需用户在 Codex 中信任，不能代替结束证据或只读采集。

默认测试使用假 adapter、进程和时钟；真实账号、原生窗口及其他电脑的兼容性需要分别验证。Codex 实验性接口或模型访问权限变化可能要求调整 `adapter.py`。
