# 界面原则

工作回顾应让人快速知道刚才完成了什么，尽量不打断正在进行的工作。

## 内容

- 每项进展一句，通常 1～2 句；信息少时可以更短，不设最低字数。
- 只保留具体结果，以及必要的影响或状态。省略操作步骤、排查过程和旁支细节。
- 已定位不能写成已修复，讨论方案不能写成已经完成。没有新成果时保持安静。
- 跨会话按工作内容归纳，跟随实际工作重心，不为每个会话平均分配篇幅。
- 默认没有标题、列表、统计和详情入口；正文不机械添加建议或免责声明。

模型决定摘要内容，界面完整显示缓存正文，不通过截句、改写或推断状态制造更短的回顾。

## 默认界面

采用独立 Windows 顶部胶囊小窗，深色背景、灰白正文，字体和留白保持轻量。平时收起，用户悬停时展开；值得看的新成果在适合的停顿时自动展示。无摘要或暂时失败只在手动查看时显示小提示。

只在本地读取缓存，悬停不调用模型，动画不抢焦点。具体尺寸、动画和窗口行为见 [原生小窗](widget.md)。

## 可选 MCP Apps 视图

`ui/` 保留可选的 MCP Apps 只读摘要视图，提供摘要与暂停／恢复。它通过宿主消息调用 `get_recap` 和 `set_recap_paused`，不直接调用模型。

该视图不是默认常驻窗口，也不代表已获得 Codex 任意侧栏或输入框区域的嵌入接口。旧 HTTP 兼容代码仅用于迁移和测试；默认后台不启动网页服务。

## 检查重点

验证正文完整可读、空状态不冒充摘要、窗口不抢焦点、悬停离开能及时收回，以及高 DPI 和目标显示器上的排版。实际流畅度和多屏行为以目标电脑的观察为准，不以计时器频率替代呈现效果。
